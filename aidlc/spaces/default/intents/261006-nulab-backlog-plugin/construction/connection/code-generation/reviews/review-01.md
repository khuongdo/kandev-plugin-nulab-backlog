| R-01 | Major | internal/connection/oauth.go > completeOAuth (lockWS before TakePending); internal/connection/service.go > lockWS and Service.locks | The OAuth callback is a public webhook (manifest `access: public`; Kandev relays it with no caller check). Any anonymous request carrying a well-formed state calls `lockWS(workspaceID)` with the attacker-chosen workspace id before anything is validated. `lockWS` inserts a channel into `Service.locks` and never deletes it, so unauthenticated requests grow the map without bound. Floods aimed at a real workspace id also queue on that workspace's write lock, which refresh, Connect, Disconnect and SetProjects share, and each non-matching request does a state read of up to 1 s under it. Every bad-state request also logs a WARN `oauth_failed`. No test covers a flood or the map size. | Check the callback cheaply before taking the lock, for example a read-only peek of `oauth_pending` for that workspace, and take the lock and TakePending only when a pending record exists. Make `lockWS` reference-counted so idle entries are removed. Log `bad_state` below WARN. Add a test that many unknown-workspace callbacks leave `len(locks)` unchanged and do not delay a Connect on a real workspace. | New |
| R-02 | Major | internal/connection/lifecycle.go > SetProjects, Service.projects; internal/connection/store.go > saveProjects | `SetProjects` gets the project list through `s.projects`, which calls `Credentials` and discards the epoch it returns. It then validates the keys against that list and takes the lock. `saveProjects` re-reads the pair and writes the keys with no check that the connection is still the one that was read. A space change or credential replacement between the read and the lock lets a selection validated against space A be stored on the connection to space B. This breaks the R-08 rule that late results must not apply to a newer epoch, and AC1.8.3. The returned epoch exists for this check. No test covers it. | Keep the epoch from `Credentials` and pass it to `saveProjects`. Return `ErrStale` (classified as `conflict` or `reconnect_required`) when `p.epoch()` differs. Add a test that changes the space between `Projects` and the write. | New |
| R-03 | Minor | internal/connection/lifecycle.go > refresh | The refresh runs on the caller's context for both the token call and `UpdateTokens`. Backlog rotates the refresh token on every refresh. If the caller is cancelled or times out after Backlog answered, or the secret write fails, the new refresh token is lost. The next refresh then gets `invalid_grant` and the user must sign in again. This heals itself but is avoidable. | Run the persist step (and ideally the token call) on a context detached from caller cancellation, with its own short timeout. Add a test where the caller is cancelled after the token reply. | New |
| R-04 | Minor | internal/connection/change.go and lifecycle.go > Current; contract-summary.md C1, C3, C5, C6 (not amended) | The code changes shared contracts: `Credentials` returns an epoch and takes a workspaceID, there is no `codeVerifier`, action keys are snake_case, there are new codes `reconnect_required` and `integration_disabled`, and the OAuth state is a server-side nonce instead of a signed state. `code-summary.md` lists these as amendments still needed, but `contract-summary.md` is unchanged. `Current` also returns `ErrReconnectRequired` in the sign-in-again state, which C3 does not allow. U3 and U4 would build against stale signatures. | Apply the listed amendments to C1, C3, C5 and C6 before U3 starts. Add `ErrReconnectRequired` to C3. | New |
| R-05 | Minor | internal/connection/oauth.go > signIn; internal/connection/service.go > connect | The callback holds the workspace lock through the code exchange, `Myself` and the store writes, up to 12 s. A concurrent API-key `Connect` takes the same lock with a 2 s store timeout after its own `Myself` call. It can fail with `internal` although the key was valid. | Hold the lock only for the final switch check and write, or give `Connect` a longer lock wait. Document the choice. | New |
| R-06 | Minor | internal/backlog/client.go > rateLimitWait and send | `X-RateLimit-Reset` is used without an upper bound. A Background call waits the whole time on each of up to 3 retries, so a wrong header can park a poller for hours. `Retry-After` given as an HTTP date is ignored, and the wait falls back to 60 s. | Cap a single wait (for example 5 minutes) and parse the HTTP-date form. The UI then shows "OAuth is not set up on this Kandev server" in place of a sign-in-again message. | Map the refresh case to a dedicated or `reconnect_required` outcome, and keep `validation`/`oauth` only for `start_oauth`. | New |

### Summary

The implementation matches the plan and its assumptions, and the secret handling is sound. State is a 256-bit nonce, hashed at rest, compared in constant time and single use. The redirect is relative with a validated workspace id. The key is sent in a header, and redaction covers codes, tokens and the state. I checked the SDK and Kandev handlers for the public webhook, the raw query, the Location header and `GetConfig`, and they behave as claimed. The deviations are acceptable: keeping the pending record on a wrong state is the right call, and the native inputs, the `GetConfig` adapter, the `TestU2_` names and the three U1 test edits are justified. Two Major issues remain and should be fixed at the gate: pre-auth lock-map growth and lock contention on the public callback (R-01), and the epoch not being checked when saving a project selection (R-02). Several Minor issues should be fixed before U3 depends on this code.
